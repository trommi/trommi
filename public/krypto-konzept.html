Trommi Krypto-Konzept

Einladungslink, Schlüsseltausch und ein Server, der Inhalte nicht lesen kann. Entwurf vom 2. Oktober 2026, noch nicht gebaut.

Kern: Ein Geheimnis im Einladungslink, das der Server nie sieht, beglaubigt den Beitritt. Ein Raumschlüssel, den nur die Teilnehmer kennen, verschlüsselt alle Inhalte. Jede Nachricht ist vom Gerät des Absenders signiert, damit ein Agent nur ausführt, was wirklich von dir kommt.

1. Einladen: der Link kommt in die KI

  1. Dein Browser erzeugt https://host/join#raum.geheimnis. Alles hinter dem # schickt ein Browser nicht an den Server.
  2. Der Channel-Prozess des Agenten erzeugt ein Schlüsselpaar und meldet den öffentlichen Schlüssel an, beglaubigt mit einem Code, der aus dem Geheimnis abgeleitet ist (HMAC).
  3. Dein Browser prüft den Code. Der Server kann ihn nicht fälschen, weil er das Geheimnis nicht kennt.
  4. Der Browser verschlüsselt den Raumschlüssel für den öffentlichen Schlüssel des Agenten (X25519) und legt ihn auf dem Server ab.
  5. Der Link gilt einmal und läuft nach wenigen Minuten ab. Ein neues eigenes Gerät tritt genauso bei, per Link oder QR-Code.

2. Im Betrieb

Inhalt. Nachrichten, Karten und Anhänge werden beim Absender mit dem Raumschlüssel verschlüsselt (AES-256-GCM). Der Server speichert und verteilt nur Blobs.

Echtheit. Jede Nachricht trägt die Signatur des Absendergeräts (Ed25519). Der Agent führt nur aus, was von einem deiner Geräte signiert ist. Für die Kontrolle von Agenten ist das der wichtigste Teil.

Reihenfolge. Fortlaufende Nummern und eine Hash-Kette je Absender: Der Server kann nichts unbemerkt weglassen, wiederholen oder umsortieren.

Browser. Alles über WebCrypto, Schlüssel nicht exportierbar in IndexedDB. Symmetrische Verschlüsselung kostet praktisch keine Zeit, der Schlüsseltausch geschieht einmal pro Einladung.

3. Was der Server sieht und was nicht

VerborgenBewusst im KlartextUnvermeidbar sichtbar
Text von Nachrichten und Karten, Optionen, Anmerkungen, Anhänge, Scribbles, Statuszeilen Kartenstatus und Zeitpunkt der Antwort (für das Löschen nach 30 Tagen), Verweis auf Anhang-Dateien, optional die Dringlichkeitsstufe Welche Konten und Geräte in einem Raum sind, wann und wie viel sie senden

„Zero Knowledge“ gilt also für Inhalte, nicht für Metadaten.

5. Bewusst einfach gehalten

  • Kein Ratchet wie bei Signal oder Matrix. Ein neuer Raumschlüssel entsteht, wenn ein Teilnehmer entfernt wird, und optional täglich.
  • Preis: Ein gestohlener Raumschlüssel macht alles bis zur nächsten Rotation lesbar. Signaturen verhindern trotzdem, dass damit Befehle gefälscht werden.
  • Wiederherstellung: Verlierst du alle Geräte, ist der Verlauf weg, außer du sicherst einen Wiederherstellungsschlüssel.
Schwachstelle des Ansatzes. Der Link ist ein Inhaberpapier: Wer ihn zuerst einlöst, ist drin. Einmalgültigkeit und kurze Laufzeit begrenzen das. Wer mehr will, bestätigt den Beitritt im Browser anhand eines kurzen Prüfcodes, den der Agent anzeigt.

6. Reihenfolge beim Bauen

  1. Geräteschlüssel im Browser und beim Agenten, Einladungslink, Schlüsseltausch. Inhalte noch im Klartext, aber Befehle schon signiert.
  2. Ereignisprotokoll statt Gesamtzustand, zunächst unverschlüsselt, mit Nummern und Hash-Kette.
  3. Inhalte verschlüsseln, Anhänge stückweise, Sprache auf die Endpunkte verlagern.
  4. Rotation des Raumschlüssels, Wiederherstellungsschlüssel, Prüfcode beim Beitritt.
